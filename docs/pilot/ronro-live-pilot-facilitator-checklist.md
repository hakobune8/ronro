# 論路 Live Pilot — 進行役チェックリスト

参加者には [ライブパイロットガイド](ronro-live-pilot-guide.md) を配布する。この文書は進行役用であり、共有画面には表示しない。

## 開始前

- 参加者への説明とデータ取り扱いの確認を済ませる。音声の永続保存はデフォルトで行わない。録音保存が必要なら事前に明示的な同意を得る。
- 使用する16:9画面で、現在の話・上部の「話の流れ」・決定候補／未解決事項／次の対応を3mと5mから人が確認する。読めない場合はPilotを開始しない。
- 本番URLの `/healthz`、`/readyz` と `/shared` を確認し、進行役は別画面で `/control` を開く。参加者はShared Viewを操作しない。
- マイク入力を確認し、新しい会議セッションが空の状態から始まることを確認する。過去の評価セッションを再利用しない。

## 会議中

- 議論の主役は参加者。論点図はときどき見ればよく、読み上げや操作を求めない。
- 指摘があれば自然な言葉で受け止める。明確な発話訂正はHuman Eventとして処理される。曖昧な発話はGraphを変更せず、進行役画面の「論点のつながりを訂正する」に最近の確認依頼を表示する。
- 対象が曖昧なら参加者に確認する。進行役画面ではNode IDを入力せず、表示された論点本文から既存のつながりと両端を選ぶ。誤結線は「外す」、元の論点が違えば選択して「つなぎ直す」、明示された新しい関係なら「つなぐ」。独立した話だと明言された場合だけ「別の独立した論点」を選ぶ。
- 送信後、Shared Viewの該当部分が変わり、進行役画面の履歴にHuman訂正Eventが残ることを確認する。確認依頼の文面は対応後も履歴として残るため、表示されているだけで未対応とは限らない。
- 決定候補を確定事項と扱わない。担当・期限を推測して埋めない。訂正できない、Graphが壊れる、音声処理が継続して失敗する場合はPilotを停止して記録する。

## 終了時

- 先に音声の取り込みを止め、STT・Analyzer・QueueのDrainを待つ。`ended`、Queue pending/processing/failedがすべて0、Graph revisionとRendered revisionの一致を確認する。
- 不完全終了や未解決の音声itemがあれば、Evidence完全性を主張しない。事実と時刻を記録し、次の会議で同じセッションを使わない。
- 参加者の感想はShared Viewの理解しやすさ、訂正のしやすさ、議論への妨げを分けて記録する。第三者の音声・全文書き起こし・私的画面をPublic Gitへ入れない。

## 本番前の短い操作練習（実会議ではない）

1. 進行役の実機で `/control` を開き、別画面で `/shared` を表示する。
2. `Start Continuous` を押し、自分で作った短い日本語の話を二つ発話する。Finalと論点図の更新を確認する。
3. 進行役画面の「論点のつながりを訂正する」を開く。線があれば一つ選び、どの話の関係かを確認してから外す。線がなければ、明確に関係する二つの論点を選んで一時的につなぎ、その線を外す。操作後に共有画面が更新されることを確認する。
4. `End Session` を押し、`ended`、Queue 0/0/0、Graph/Rendered revision一致を確認する。練習結果と気になった操作を連絡する。練習用の表示を本番参加者へ見せたままにしない。

実機練習では、担当・期限や決定の確定を試しに作らない。訂正対象が曖昧なら、無理につながず確認する。

## 現在の受け入れ状態

候補は本番URLへdigest固定で反映済み。短い合成音声テスト、ローカル訂正テスト、本番Live APIを通る合成音声＋Human訂正テストは通過した。新レイアウトの実距離3–5m確認はHumanから「読める」と回答済み（実測解像度は未記録）。進行役の実機での訂正練習は未完了。これを通過するまではPilot開始可と宣言しない。
