# Discussion Relation Model Spike — evidence-gated architecture review

Status: offline investigation; no Product/schema/Analyzer change. T1/T2 audio was not rerun. The private Human Review comparison is outside Public Git.

## Source priority and present model

The MVP RD makes the meeting-time Discussion Map primary and minutes secondary. RFC 0001 separates Evidence, Event history, and current Graph, and recommends few precise relations rather than speculative `related_to` edges. RFC 0003 separates Topic transition history from semantic containment and asks the live map to show the current Topic's neighborhood. RFC 0005 treats post-meeting output as Graph state plus Event history, with Evidence for traceability. These intentions outrank the older offline visualization hypothesis.

The implemented Canonical model is narrower than RFC 0001's conceptual relation list:

- A **Node** is a stable semantic entity with type `topic`, `idea`, `option`, `concern`, `open_item`, `decision`, or `action`, a full label, lifecycle status, Event provenance, and Evidence references. It is not one transcript turn or one card. An optional `display_label` is non-canonical Presentation metadata.
- A **Topic** is a durable branch/container Node. `current_topic` is a separate current-focus state; one Topic can contain multiple subthemes. Topic identity is neither a presentation root nor an utterance sequence.
- A **Relation** is a typed Graph Edge created by `relation_detected`, currently `contains`, `has_option`, `supports`, `opposes`, or `related_to`. `contains`/`has_option` are structural. `supports`/`opposes` are semantic but directional. `related_to` is permitted by schema but conveys little defensible meaning. Edge `source_event_ids` lead to Events' `source_evidence_ids`; the edge itself does not carry Evidence IDs. Materializer rejects self-edges, invalid type pairs, and archived endpoints and deduplicates an identical typed endpoint pair.
- **Decision** is already a Node (`candidate` → human-confirmed `confirmed` → possibly `revoked`). **Open Item** is a Node (`active`/`resolved`). **Action** is a Node with separate description, explicit-or-null owner and due, and action status. These are durable outcome/issue entities with lifecycle, not merely rail badges or states of an ordinary Idea. Their origins may involve another Node, but current schema does not express a precise issue→resolution or decision→action edge. The Shared View rail is a projection of these Nodes, not their Canonical ontology.
- Event sequence and timestamps are Canonical **history**. Sequence may justify “discussed next” or a Topic return in a temporal strip; it does not prove a semantic Node-to-Node Relation. In particular, a return to an earlier Topic is a focus/history fact, not automatically `supports`, `opposes`, or a new semantic edge.

The Analyzer v3 output can already emit relation intents in the same inference. Its current instruction defaults to 0–2 per utterance, favors Topic containment, and permits semantic edges only when explicit and useful. The adapter validates endpoint types and requires referenced Evidence from the current utterance. It can reference existing Nodes as well as newly created ones, so **late relations are structurally possible**, although the context builder's limited active/recent Node window can make distant older endpoints unavailable. A new enum alone would not solve retrieval, extraction precision, or provenance.

## Empirical check: T1 and T2

T1 is the best completed run: 53 Finals, 38 Nodes (one Topic; 32 Ideas, four Concerns, one Option), 31 Edges, and revision 72. **All 31 Edges are `contains`**; 37 distinct Evidence IDs are referenced by Nodes. T1 contains zero Decision/Open Item/Action. The saved Graph and 5/10/15-minute snapshots contain labels, Evidence IDs, and ordering. The accessible retained artifacts do **not** contain the corresponding speech text or raw Analyzer response. The earlier post-run 53-Final timeline contains reviewer paraphrases, expressly not quotations. Consequently a label-to-label resemblance cannot be promoted to an Evidence-defensible semantic edge. This is a source limitation, not a conclusion that the speakers never expressed relationships.

A representative **16-transition annotation** was made in natural-language terms before considering enum values. Five look like possible elaboration/example, two like possible problem→response, two like qualification/contrast, two like comparison/alternative, and five like a switch, return, synthesis, or independent branch. These are **screening hypotheses**, not accepted relations: 0/16 have accessible utterance text sufficient to validate the proposed semantic claim. Several adjacent pairs are clearly only temporal transitions; none becomes a Canonical semantic Relation on this review. Verified Node-to-Node coverage: 0; verified independent roots: 0; verified multiple-parent cases: 0; uncertain evidence-dependent pairs: 16. “No incoming semantic edge” therefore means **unlinked/unknown**, not a proven independent root. See the private artifact for the pair-by-pair table and source-index references.

T2's saved failed-run short Graph has 12 Nodes and 11 `contains` Edges, including one Open Item. The retained Evidence/Utterance records available here are metadata, not speech text. The later T2 run's four empty Provider items (about 5.248 seconds) remain a separate completeness limitation; no missing content or relation is inferred from them. Synthetic fixtures exercise supported edge types and lifecycle transitions, but cannot establish relation precision on real discussion.

## What is missing, and what is not

For **Live Focused Flow**, recency, Event sequence, current Topic, existing `contains`, and a latest-detail panel can already answer “what changed most recently?” They cannot truthfully answer “why did point B develop from point A?” unless Evidence supports a typed semantic link. For a **Final multi-root map**, the same state can show Topic groups and chronological movement, but treating every unlinked Node as a distinct semantic root or drawing causal arrows would overstate the record. Overview/detail layering is needed independently of any new Relation schema; rendering all 38 T1 Nodes at once would be unreadable.

Conceptual Live and Final projections **can share the same Graph plus Event history**. They need not share a layout. Live may show a 3–5-Node local chronological neighborhood and verified semantic links, with the latest full Canonical Node in a separate detail area. Final may show several Topic/issue entry points, verified branches, status outcomes, chronological transitions, and drill-down to full Node/Evidence. Without verified links the honest common projection is sparse and sequence-aware, not a fabricated mind map. Candidate/confirmed Decisions, unresolved Open Items, and Actions may appear both as graph outcomes and in a separate status rail, but the rail does not create origin relationships.

## Minimal model assessment — not a schema proposal yet

Do **not** introduce a new Relation enum on this dataset. The existing `contains`, `has_option`, `supports`, and `opposes` already cover structure, option membership, and two precise argumentative claims, but T1 provides no verified examples of the latter two. `related_to` should not be used as a placeholder for visual connectedness. Potential missing semantics to test with actual speech are: **elaborates/example-of**, **addresses/resolves an issue**, and **results-in an action**. These are questions for evidence review, not approved types. Direction would matter for elaboration and outcomes; contrast may be symmetric in ordinary language but current `opposes` is directed to a proposition, not a generic “different from.” One source statement could support multiple parents, and an unrelated new discussion point must be allowed to remain unattached.

For outcome chains, Issue/Option/Decision/Action are already separate Node types where the issue is a durable Open Item; an ordinary Concern is not automatically an unresolved question. A Decision's candidate/confirmed lifecycle is independent of an origin edge. A future `resolves` relation should not by itself confirm a Decision or resolve an Open Item; those require their own lifecycle Events. Likewise a future Decision→Action link cannot create an Action or infer owner/due. Human correction would require add/remove/retype Events, never direct Graph mutation. Late Evidence may warrant adding or retracting an edge, but the current Event contract has addition only; that change should wait for the evidence-backed taxonomy.

Canonical should retain only assertions that have high-precision, auditable meeting meaning. Visual roots, recency ranks, focus layout, dotted chronology, density reduction, and latest-detail placement remain Projection metadata. A semantic Relation should have traceable Event Evidence from the utterance that **states the relationship**, not merely the two endpoints' separate Evidence. False positive edges can imply unsupported causality, adoption, or resolution and are more harmful than absent edges. Deterministic checks (valid endpoints/type, self-edge, duplicate, lifecycle, evidence IDs) protect structure but cannot establish semantic truth.

## Evaluation and impact if a type is later justified

First perform blinded human annotation on accessible speech with “none/uncertain” allowed. Measure per-type precision first, then recall against adjudicated Goldens, reviewer agreement, false outcome/causality rate, and usability gain over sequence-only Live/Final views. Pilot should favor sparse high-precision edges; no target recall is asserted yet. Keep older Graphs with zero semantic edges valid and show sequence without synthetic connectors.

If evidence supports a new type, the likely scope is Analyzer Output Schema and prompt, Event/Graph schema enums and allowed endpoint matrix, adapter validation, Materializer replay/deduplication, correction Events, projection rendering, and compatibility tests. Same-call extraction could avoid a second LLM call, but late links require adequate retrieval of prior Nodes and an Event whose Evidence actually establishes the link. Model-side confidence scores are not proposed. A reversible correction path is especially important for a wrong Decision/Action-origin edge.

**Decision: D. MORE EVIDENCE REQUIRED.** The existing Graph is sufficient to construct a truthful sequence-aware view; it is not shown sufficient for a semantic relation map, but a new relation type is not justified by the retained T1 material. The offline Human Review artifact deliberately shows zero solid T1 semantic links and distinguishes “unlinked” from “independent.” T2 audio, Product, and deployed UI remain unchanged; RFC-0006 remains pending.

**Follow-up correction:** T1 is an empirical workload, **not** Ground Truth for a general Relation model. The next work was therefore broadened into a small [cross-archetype Relation Evaluation Corpus](../../evaluation/relation-corpus/README.md) covering exploratory, technical, option-comparison, decision-making, and execution-planning discussions. T1/T2 remain unverified real-world probes where the accessible utterance Evidence is absent; no semantic link is inferred from their final Graphs. That Corpus Spike's single further step is blinded Human annotation plus a small Evidence-complete real-world sample across discussion styles, not T1-only recovery or taxonomy adoption. Do not rerun T1/T2 for this correction.
