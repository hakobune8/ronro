# Minimal Semantic Graph — hypothesis implementation

Status: **WORKING PRODUCT HYPOTHESIS / Human Review pending**. This is not a validated final Relation taxonomy. Nothing in this implementation deploys a new Shared View or reruns T1/T2.

## Existing contract and narrow addition

Before this work the Canonical Graph accepted `contains` (Topic→discussion Node), `has_option` (Topic→Option), directional `supports`/`opposes`, and legacy `related_to`. Edges are materialized from `relation_detected` Events; each Edge stores source Event IDs, while the Events store Evidence IDs. Replay is ordered and deterministic. Decision, Open Item, and Action are stateful Nodes; Relation creation does not change their lifecycle. Topic Return is focus/Event history, not an Edge.

Three names considered: `discussion_provenance`, `arose_from_discussion_of`, `emerged_from_discussion_of`. **`discussion_provenance`** was chosen because it is compact, applies to Issue→Option, Option→Decision, Decision→Action, and Open Item→Action, and avoids physical causality. It means only: *target B arose in discussion of source A*. It does not mean cause, proof, support, opposition, resolution, or mere temporal adjacency.

The Canonical Domain/Event and Analyzer output v1/v2/v3 schemas admit exactly this one additional type. The Materializer admits non-Topic→non-Topic endpoints, requires a nonempty reference to existing linking Evidence, rejects self/archived/invalid endpoints, deduplicates identical typed endpoints, and rejects provenance cycles both on addition and after Human Node merge. Several parents remain valid. Existing Graphs and `related_to` Events still replay. `related_to` is not proposed in the opt-in hypothesis Analyzer mode.

Structural validation cannot prove semantic truth. The Analyzer prompt requires current-utterance Evidence for each link, favors no Edge over a speculative one, forbids sibling-Option and Topic-return shortcuts, and discourages redundant transitive shortcuts unless independently supported. No relation infers Decision confirmation, Open Item resolution, Action existence, Owner, or Due. Human correction of a wrong relation is a future design need; the current Event catalog has addition and Node merge, not an explicit remove-relation command.

## Analyzer and discussion-time evolution

The opt-in `analyzer-prompt-v6-semantic-graph-hypothesis` proposes Nodes and Relations in **the same inference**; no second LLM call. Existing prompt versions and deployed behavior remain unchanged: older prompt versions reject the new intent even though the additive schema can parse it. New→existing, existing→new, and later existing→existing links use the existing flat reference contract. A later utterance can therefore connect already-present Nodes without recreating them. Only the linking utterance's Evidence IDs are accepted by the Analyzer adapter.

To make late links reachable, v6 selects a bounded set of old Nodes across Topics using deterministic phrase overlap, current-context membership, and recency. This is retrieval, **not** semantic relation inference. The 32-Node context budget and paraphrased references can still miss an old Node; an absent Edge is safer than a guessed one. Candidate generation rejects v6 references outside the shown context, provenance cycles, and new legacy `related_to` intents. Materializer remains the final validator.

## R1–R5 regression and limits

The controlled corpus contains 27 Nodes and 31 candidate pairs. The reviewed minimal classification is `supports` 2, `opposes` 1, provenance 12, no direct semantic Edge 14, uncertain 2. The authored **replay stream** accepts the 15 positive Edges, omits 14 none and two uncertain pairs, and preserves multiple roots. It includes R2's non-causal technical hypotheses, R3's sibling Options without an alternative edge, R4's Issue→Option→Decision path without a shortcut, and R5's Decision/Open Item→Action paths without lifecycle mutation. No Edge is fabricated for a Topic Return. Cycle, duplicate, missing Evidence, late connection, multiple-parent, cross-Topic retrieval, replay, and lifecycle tests pass.

These are hand-authored, Evidence-backed controlled Event proposals. **Actual model-generated R1–R5 Relation precision/recall was not measured**: no local provider credential was available. Thus “15 accepted / zero false in replay” is a structural test result, not an Analyzer quality score or real-world prevalence estimate. T1/T2 lack accessible complete utterance Evidence for relation annotation and are not treated as Goldens.

## Projections from the same Canonical Graph

`prototype/semantic_projection.py` provides deterministic, opt-in functions; the deployed six-card Shared View is unchanged.

- **Live Focused Flow:** latest meaningful non-Topic Node is the focal point; a later Topic focus event can move to its latest child. Include direct provenance parents/children, argument neighbors, then useful second-hop context, up to five Nodes. Never fill with unrelated Nodes. A new independent root can become focus with only one visible Node. Edges display only accepted semantics; Event chronology remains separate. Display labels serve the overview; the latest added/materially updated Node's full Canonical content remains in a separate detail area.
- **Final multi-root map:** Nodes without incoming provenance are labeled *entry/unlinked*, not proven independent. Show a capped overview, argument links distinct from provenance branches, all Canonical details separately, and Topic/Node Event chronology separately. The final artifact does not turn sequence into semantic arrows.

R1–R5 private HTML compares (A) current six cards, (B) a connected discussion-time Focused Flow plus latest detail, and (C) a multi-root post-meeting map. The review should ask whether lines explain origin without implying causality, whether the current point is obvious, whether R3/R4/R5 chains are readable, and whether sparse/unlinked branches look honest. The artifact is a conceptual comparison, not a production or 3–5m visual acceptance.

Generate the private artifact with `python -m evaluation.tooling.semantic_hypothesis_review --output <private-path>/index.html` using the repository's development dependencies. Do not commit the generated HTML/screenshots if private evaluation data is later added.

## Runtime acceptance and Correctable Working Graph follow-up (2026-09-23)

The Product interpretation is now a **correctable working Graph**, not an immutable AI answer. A plausible wrong provenance parent is a Class 1 error only if a participant can remove/change it, the correction persists in Canonical Event history, and old Evidence cannot silently recreate it. This does **not** relax Decision confirmation, Action/Owner/Due, negation, Evidence, or Graph safety. The preceding paragraph records the earlier hypothesis stage; the following results supersede its statement that relation removal is only a future need.

### Actual Analyzer R1–R5 acceptance

The actual same-inference Analyzer path (`gpt-5.6-luna`, medium effort, output schema v3) ran three clean sessions per controlled archetype, 15 sessions total. It saw only spoken Evidence/current Graph, not Human-reviewed pair answers. A versioned v6 baseline was followed by one focused v7 prompt/safety iteration and a complete R1–R5 rerun. The private run and scoring artifacts are outside Public Git. T1/T2 audio was not replayed.

In v7, the generated Graph contained 14 semantic Edges across 15 sessions: eight provenance, three supports, and three opposes. Evidence-anchored matching to the selected 31-pair Corpus found 11 expected direct-edge hits, 26 misses among pairs with matched endpoints, 32 correctly unconnected candidate pairs, and 24 pairs that could not be compared because a Node endpoint was missing. Three generated Edges fell outside the 31 selected pairs; they appeared plausible on inspection but remain Human-review items, not automatic false positives or precision credit. There were no edges on the selected no-direct-edge pairs. This selected Corpus is a boundary test, not a prevalence estimate. A single global “precision” number would misleadingly mix unmatched Nodes, unreviewed extra edges, and controlled author interpretation.

The main failure is **coverage/stability, not dense false lines**. R1 produced 0/2/1 semantic Edges across runs; R2 produced 3/0/0; R3 produced 1/2/2; R4 produced the correct supports Edge in each run but no candidate Decision; R5 produced no semantic Edges. The R4 Decision candidate is absent in all three runs, so Option→Decision cannot be evaluated. R5 starts from a Human-confirmed Decision in the controlled scenario, but the fresh Analyzer run did not preload that command or fabricate a prior Decision. Consequently Decision→Action cannot be evaluated there either. R5's explicit Actions and Japanese-format due date were accepted after a deterministic equivalent-date check; no Owner/Due was inferred from absent speech.

The v6 baseline incorrectly admitted an Action from the chair's candidate-decision confirmation procedure in all three R4 runs. The v7 deterministic safety guard rejected the same incorrect *proposal* in two of three runs; the third produced no intent. Thus accepted Class 3 Graph errors = 0 in v7, but Class 3 raw proposals = 2 and the intended candidate Decision is still missing. This is not ready for a deployment candidate. The behavior guard and opt-in prompt are local only; default deployed prompt remains v4.

### Human correction loop — local hypothesis implementation

The existing Human Command→append-only Event→Materializer path now supports one `correct_relation` Event with old/new typed endpoints: remove, add, change endpoint, or change `supports`/`opposes`/`discussion_provenance` type. Human speech Evidence, when present, is attached to the correction Event; the AI proposal Event and the correction Event both remain in history. Replaying that history reproduces the corrected Graph. The Event records the Evidence-sequence watermark at correction time. Both Analyzer adapter and Materializer refuse to recreate a Human-rejected typed edge from Evidence at/before the watermark; a later, genuinely new Evidence sequence may support a fresh proposal. This is session-scoped memory, not permanent suppression.

A deliberately narrow spoken interpreter uses the current local Graph for explicit phrases such as “その二つは関係ありません”, “これは別の論点です”, “これはさっきの○○の話から出た”, and “この懸念はSMSではなくアプリ案についてです”. It resolves only a unique visible/referenceable edge and otherwise exposes a clarification request without changing the Graph. This is an initial controlled correction loop, not evidence of general conversational-language coverage or successful real-microphone correction. Relation correction never changes Decision/Open Item/Action lifecycle fields. The corrected node remains visible as unlinked or, when the Human explicitly declares independence, a verified presentation root.

### Error classes and deployment interpretation

For v7's accepted 14 semantic Edges, the selected-pair check found 0 known false direct edges. The three unselected Edges require Human review; the data cannot establish a definitive Class 1/Class 2 count. Known Class 3 **accepted** errors were 0; two unsafe Action proposals were blocked before Event creation. Missing expected links (26 with matched endpoints) are structurally significant Class 1 omissions; Human correction alone cannot make this Analyzer output a useful multi-branch working map without participants doing too much construction. More importantly, R4's candidate Decision is missing in all runs. The remaining errors are therefore **not acceptable for deployment merely because corrections now exist**. Phase A is `A3 NODE GENERATION PREVENTS RELATION EVALUATION` for R4/R5 outcome chains, with `A4`-like variation in provenance coverage. The deployment gate is **NOT READY**; no Kubernetes deployment or T1/T2 rerun occurred.

The private review entry point compares actual Analyzer Graph, Focused Flow, and Final Map for each of the 15 runs. The Focused Flow artifact separates provenance backbone from supports/opposes annotations; the Final Map distinguishes Human-declared independent roots from relation-unconfirmed Nodes. A 1920×1080 Chromium screenshot was rendered for representative cases, but physical 3–5m readability and Human semantic review remain pending. RFC-0006 remains provisional.

### Macro discussion flow in the candidate Shared View

The Focused Flow candidate keeps the existing upper 「話の流れ」 band. It displays accepted Topic focus history, not semantic Node Relations: the current Topic is leftmost, followed by recent earlier Topics, including a return to a previous Topic. Even a single Topic remains visible as the meeting's broad location. ### Same-inference Analyzer candidate acceptance (v8/v9)

An opt-in v8 prompt fixed the explicit candidate-decision interpretation that v7 missed: R4 generated one candidate Decision in all three clean real-provider runs, with zero procedural false Actions. V9 additionally removed legacy Topic-edge precedence that suppressed distinct Evidence-backed Node-to-Node proposals. A deterministic v9-only guard rejects `opposes` proposals when the current utterance states only a drawback and no explicit opposition/inapplicability; this is a narrow Class 2 protection, not a semantic proof.

After that guard, v9 ran R1–R5 from fresh state three times each (15 real-provider sessions, same Analyzer inference, output schema v3). Evidence-anchored comparison to the 31 selected Corpus pairs yielded 25 expected direct-edge hits, 12 misses with matched endpoints, 37 correctly unconnected pairs, and 19 pairs with an unmatched endpoint. Two generated R3 argument edges fell outside the selected pair set; inspection of the controlled Evidence found each interpretable as support/opposition to the generated Option, but they remain Human-review items, not automatic precision credit. R4 produced candidate Decision 3/3, false Action 0/3, and three to four semantic edges per run. R5 generated two explicitly described Actions with no invented Owner/Due, though the controlled case's prior Human-confirmed Decision was intentionally not preloaded, limiting Decision→Action comparison. No T1/T2 audio or third-party source was rerun.

This is meaningful improvement over v7's sparse graph and absent R4 Decision, but not proof of real-world Relation accuracy or 3–5m readability. Missing edges remain, and the controlled Corpus is a boundary set rather than a population sample. Human correction/replay tests passed locally. Deployment and a short smoke are recorded below; physical distance-readability and real meeting correction behavior remain to be verified before Pilot readiness.

### Participant-facing Shared View contract

The Human-supplied Live Pilot guide is the participant contract: the meeting belongs to participants, no Shared View operation is required, and the facilitator handles needed correction. Crucially, the guide also promises that participants can see **what is being discussed now, what is becoming decided, and what remains unresolved**. The private 1920×1080 Focused Flow preview therefore keeps the current discussion as the primary area and restores a separate, participant-facing state rail: `決定候補` (distinct from `確定事項`), `未解決事項`, and `次の対応` when present. Empty candidate/open categories say `まだありません`; an empty Action section does not consume space. Actions retain structurally explicit owner/due. The latest Canonical detail remains secondary. The stage does not foreground `Graph`, `Node`, `Canonical`, relation enum names, revision, confidence, or instructions to correct the AI. Developer terms and hit/miss comparison remain in separate review controls. Browser-rendered R4 and R5 1920×1080 samples were inspected for the empty-state and active-state cases; these are not physical 3–5m acceptance. At the time of this participant-contract review, the deployed six-card Shared View remained unchanged; the later candidate deployment above supersedes that status. Natural spoken corrections are an optional supported path, **not** a request for participants to interrupt or monitor the map continuously; ambiguous corrections are left unchanged for facilitator review.
