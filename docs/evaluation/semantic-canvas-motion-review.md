# Semantic Canvas motion review (synthetic)

This review uses synthetic Japanese meeting content and the actual Shared View browser renderer. It tests presentation transitions, not STT or Analyzer quality. No real meeting recording, transcript, or provider output is included.

The 21 scenes cover: empty Canvas; issue and response; supports and opposes; sibling options; Open Item; an independently confirmed discussion entry; branch return; late relation; relation correction; Candidate Decision and explicit Human confirmation; Action; long Canonical subtitle; 15, 30, 60, and 100 Nodes; and meeting-end zoom-out. Node and subtitle timestamps are synthetic graph-update times, shown in Japan time. The expanded 15–100 Node cases are load/semantic-zoom fixtures, not realistic generated meeting semantics.

Regenerate locally from the repository root:

```sh
PYTHONPATH=. .venv/bin/python tests/canvas_motion_fixture.py > tmp/canvas-motion-scenes.json
.venv/bin/python -m prototype.server --host 127.0.0.1 --port 18080 --live-ws-port 18765
# In another terminal, with Playwright available in NODE_PATH:
node tests/canvas_motion_video.cjs
```

The generated 1920×1080 MP4 is `tmp/ronro-semantic-canvas-motion.mp4`; it is intentionally ignored by Git. The frame images are under `tmp/canvas-motion/`, including a lossless `final-review.png` for inspecting relation arrows without JPEG compression. The browser renderer checks focus, the five-Node Live limit, timestamps, scrolling, and Final markers. Unit tests check event progression, a no-crossing return/correction case, and explicit Candidate-to-Confirmed transition.

To reduce short orphaned wraps without shrinking text, Live Node width is 390 px (previously 360) and Final representative width is 290 px (previously 240). Display-only Japanese word segmentation keeps short terms such as 「通行止め」 together, while `auto-phrase`/`pretty` wrapping chooses natural line breaks where the browser supports it. Unusually long individual tokens remain breakable as a safety fallback. The Final callout collision spacing is increased accordingly. Browser QA checks primary/card overlap, clipping, and label overflow; the motion fixture checks that 「通行止め」 is intact and short Option/Decision labels remain one line at 1920×1080. Canonical text and font sizes are unchanged.

The faded peripheral layer sits behind primary Nodes, so it may share screen space without obscuring primary text. Semantic lines have no text labels; compact arrowheads mark their direction without covering Node text. Blue open arrows show discussion development, green filled arrows show support, and warm single-notched arrows show opposition. The original red double-chevron was mistaken for a duplicated arrowhead and has been replaced with one head. Distinct relations entering the same side of a Node retain separate ports. These arrows describe discussion relations, not physical causality. At meeting end, independently confirmed discussion entries have a subtle solid outline, while nodes whose discussion-origin relation is still unconfirmed retain a dashed outline. Neither receives a participant-facing root-status caption: the Node's own label communicates its subject. Representative branches and Decision/Open Item/Action callouts remain on the same Canvas. To avoid overlap, callouts may move slightly; a bounded final-view adjustment also tries nearby positions when lines cross or pass through another card. New Live relations may also move an endpoint to a nearby free position when that reduces line crossing or line-through-card conflicts. These Presentation positions may change during a meeting; Canonical Graph content and accepted Relations do not. Movement is conditional, deterministic, and does not guarantee every graph is crossing-free. Final semantic lines terminate just outside the displayed callout borders rather than at invisible original node boxes. Only relations whose two endpoints are shown receive a line. Final lines are continuous. The previous faint dot-to-callout leaders and detached zoomed-out world edges are removed. The video contains no test-only text overlay. The local browser QA also checks fixed Node width/type size during focus changes and counts for currently active Nodes by participant-facing category. The video does not establish physical 3–5 m readability or real Analyzer behavior.

For a Final crossing-specific diagnostic, the R4 synthetic Graph can be rendered with the bounded Final callout repair temporarily disabled and with normal rendering. The browser QA saves both 1920×1080 screenshots privately. In this case, the unadjusted view has a crossing; normal rendering has zero line crossings and zero lines passing through unrelated cards. `tmp/ronro-canvas-crossing-reflow-comparison.mp4` shows the unadjusted view first, then the normal Final view at the same camera position. This is a before/after diagnostic cut, **not** an animation that runs during a meeting. The fixture does not establish that every possible Graph can be made crossing-free.

The separate synthetic Live reflow fixture exercises the real projector and browser renderer: two existing lines are shown, then a late third Relation would cross one of them. It supplies an explicit diagnostic-only starting geometry to make that collision reproducible; Product placement does not use this seed. The projector moves one existing Node only after it finds a lower-conflict free position. The Shared View animates the Node and Auto Camera calmly, temporarily fades connectors while endpoints move, and then shows the updated lines. Run `PYTHONPATH=. .venv/bin/python tests/canvas_live_crossing_fixture.py > tmp/canvas-live-crossing-scenes.json`, followed by `node tests/canvas_live_reflow_video.cjs` with the local server running and Playwright in `NODE_PATH`. The private output is `tmp/ronro-canvas-live-crossing-reflow.mp4`. This illustrates conditional local reflow; broader re-layout is permitted when demonstrably more readable, but is not claimed by this fixture. Both Live and Final semantic lines use darker colors and heavier strokes than the previous candidate (Live 4–4.2 px in Canvas coordinates, Final 5 px on screen). A brief low-opacity transition remains while endpoints move; settled connectors return to full opacity. Browser QA checks the settled stroke widths.

Canvas v2 derives Product positions and current focus from the accepted Graph, ordered Events, and the same `focused_flow` rule used by conversational correction. A cold replay therefore reproduces the Canvas seen during incremental rendering, including after Relation correction; a discardable exact-input cache is only a performance aid. The Auto Camera keeps its selected neighborhood above the Canonical subtitle area and omits a lower-priority neighbor when the readable scale cannot accommodate all of them. The synthetic videos and browser checks do not replace a long-session latency or real-meeting usability evaluation.
